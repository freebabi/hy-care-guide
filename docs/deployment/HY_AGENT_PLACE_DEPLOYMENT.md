# HY CARE GUIDE 배포 안내 (HY AGENT PLACE · Docker)

이 문서는 HY CARE GUIDE를 사내 앱 플랫폼(HY AGENT PLACE)에 Docker 이미지로 올릴 때 필요한 설정을 정리한 것입니다.
**환경변수는 이름과 용도만 적었습니다. 실제 값(비밀번호·비밀키·사번 등)은 이 문서·코드·Git 어디에도 적지 않습니다.**
플랫폼의 내부 주소도 적지 않았습니다. 플랫폼 화면의 안내를 따르세요.

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 실행 포트 | 8000 (컨테이너 안) |
| 실행 환경 | Node.js 22 (Next.js 16, 앱 요구 Node 20.9 이상) |
| 이미지 | 저장소 루트의 `Dockerfile` (2단계 빌드, 일반 사용자 `node`로 실행) |
| 시작 명령 | `sh ./docker-start.sh` (`scripts/docker-start.sh`가 이미지에 복사됨) |
| 주소 앞부분 | 플랫폼이 시작 때 `APP_BASE_PATH`로 주입 → 코드에 값을 적지 않음 |
| 서버 데이터 | `APP_DATA_DIR` 폴더의 JSON 파일 |

## 2. 환경변수

| 이름 | 누가 넣나 | 용도 | 비었을 때 |
|---|---|---|---|
| `SESSION_SECRET` | 배포 환경의 비밀값 설정에 입력 | 로그인 쿠키 서명 키(16자 이상 임의 문자열) | 로그인 API가 동작하지 않음 |
| `ADMIN_PASSWORD` | 배포 환경의 비밀값 설정에 입력 | 관리자 로그인 비밀번호 | 관리자 로그인 비활성 |
| `ADMIN_EMPLOYEE_ID` | 배포 환경의 비밀값 설정에 입력 | 관리자 1명의 사번 | 관리자 로그인 비활성 |
| `ADMIN_NAME` | 배포 환경의 비밀값 설정에 입력 | 관리자 1명의 이름 | 관리자 로그인 비활성 |
| `APP_DATA_DIR` | **배포 환경이 자동 주입**(직접 입력하지 않음) | 서버 데이터 저장 폴더 | 임시 폴더(`/tmp/hycg-data`)를 쓰며 재배포 시 데이터 사라짐(시작 로그에 경고) |
| `APP_BASE_PATH` | **배포 환경이 자동 주입**(직접 입력하지 않음) | 앱 주소의 앞부분(예: `/apps/앱이름`) | 루트(`/`)에서 실행 |

- 관리자 3요소(`ADMIN_PASSWORD`·`ADMIN_EMPLOYEE_ID`·`ADMIN_NAME`)는 **셋 모두** 있어야 관리자 로그인이 켜집니다.
- 비밀값은 배포 환경에 입력한 뒤 **다시 배포**해야 적용됩니다.
- 시작 스크립트는 비어 있는 필수 변수의 **이름만** 로그에 경고하며, 값은 출력하지 않습니다.
- 로컬 개발용 예시는 `.env.example`(값 없음)에 있습니다. 실제 값이 든 `.env*` 파일은 Git과 Docker 이미지에 들어가지 않습니다(`.gitignore`, `.dockerignore`).

## 3. APP_BASE_PATH 동작 방식

Next.js의 `basePath`는 **빌드할 때 고정**됩니다. 플랫폼은 배포 시점에야 값을 알려 주므로 다음과 같이 처리합니다.

1. **빌드**: `APP_BASE_PATH=/__APP_BASE_PATH__`(자리표시)로 빌드합니다. (`Dockerfile`)
2. **시작**: `scripts/docker-start.sh`가 빌드 결과물 안의 `/__APP_BASE_PATH__`를 플랫폼이 준 실제 값으로 바꾼 뒤 서버를 시작합니다.
   - 앞뒤 `/`·공백을 정리하고, 영문·숫자·`.`·`_`·`~`·`-`·`/` 이외 문자와 `.`/`..` 구간은 거부합니다.
   - 값이 비어 있으면(루트 실행) 자리표시를 지웁니다.
   - 한 번 적용한 컨테이너를 **다른 값으로 다시 시작**하면 오류로 멈춥니다(컨테이너를 새로 만들어야 함). 같은 값으로 재시작하는 것은 문제없습니다.
3. **코드**: `src/lib/care-guide/base-path.ts`의 `withBasePath()`가 아래 항목에 앞부분을 한 번만 붙입니다.
   - `fetch("/api/…")`(모든 API 호출은 `me-api.ts`·`session.ts` 등에서 이 함수를 거침)
   - 로고·안내 이미지(`<Image src>`), CMS 이미지 링크, OG 이미지
   - 밖으로 공유하는 전체 주소(문자·QR·알림톡 링크)
   - `<Link>`, `router.push`, `/_next/…`(스크립트·CSS·글꼴)는 Next.js가 자동으로 붙이므로 **손대지 않습니다**(두 번 붙으면 오류).
4. **쿠키**: 로그인 쿠키의 `Path`는 앱의 하위 경로(루트 실행이면 `/`)입니다. 같은 서버의 다른 앱에는 쿠키가 전달되지 않습니다.

## 4. 로그인 쿠키(`hycg_session`)와 HTTP/HTTPS

- 사내망 주소가 **http**인 경우 `Secure` 쿠키는 브라우저가 저장하지 않아 로그인이 되지 않으므로, 요청이 실제로 HTTPS일 때만 `Secure`를 붙입니다.
- 판단 순서: `X-Forwarded-Proto` → `Forwarded: proto=` → 요청 주소의 프로토콜.
- 앞단에 HTTPS 프록시가 있다면 **`X-Forwarded-Proto: https`를 전달**해 주어야 `Secure`가 붙습니다. (전달하지 않으면 쿠키는 `Secure` 없이 발급됩니다.)
- `HttpOnly`, `SameSite=Lax`, 서명(HMAC)은 항상 유지됩니다. 유효기간은 12시간입니다.

## 5. 서버 저장소(APP_DATA_DIR)와 공유 데이터

모든 사용자가 같은 내용을 보도록, 아래 데이터는 `APP_DATA_DIR` 폴더에 JSON 파일로 저장됩니다. 브라우저(localStorage)에는 저장하지 않습니다.

| 데이터 | 파일 | 누가 쓰나 | 누가 보나 |
|---|---|---|---|
| CMS 콘텐츠 변경분(관리자가 수정·등록한 안내, 의료 검토 상태) | `cms/guides.json` | 관리자만 | 직원 전체 / 환자는 "게시 + 의료진 검토 완료"만 |
| 개선 요청 | `cms/requests.json` | 로그인한 직원 | 관리자 전체, 일반 직원은 본인 요청만 |
| 첨부 파일(안내문 원본, 개선 요청 첨부) | `cms/files/…` | 관리자 / 요청자 | 직원(안내문 원본) / 요청자 본인·관리자(요청 첨부) |
| 복구 직전 자동 복사본 | `cms/backups/<시각>/` | 복구 실행 시 자동 | 서버 관리자 |
| 직원 등록·접속 기록, 내 보관함, 활용 이력, 공지 | 기존 파일들 | 각 기능 | 기존과 동일 |

- **기본 안내 88건은 코드에 포함**되어 있고 서버 파일에는 "변경분"만 있습니다. 관리자가 기존 안내를 수정하거나 비게시로 바꾸면, 같은 ID의 서버 기록이 코드의 기본 안내를 대신합니다(코드는 그대로). 기존 안내의 ID·주소(slug)는 바꿀 수 없습니다.
- 일반 직원에게는 "게시 중인" 콘텐츠만 내려가며(검토 대기 중인 게시 콘텐츠는 직원에게 보임), 비게시·폐기 콘텐츠는 관리자만 받습니다.
- 환자 화면(`/c/…`)은 로그인 없이 열리며, 서버가 "환자에게 공개해도 되는" 콘텐츠만 내려 줍니다(검토 대기·비게시는 응답에 아예 없음).
- 인쇄·내려받기·환자 안내(문자·QR)·안내 제공 기록·자료 묶음은 **서버가 검토 대기 콘텐츠를 거부**합니다(화면 버튼 비활성화와 별개).
- 개선 요청과 첨부에는 환자 개인정보를 쓰지 않도록 안내하고, 주민등록번호·전화번호처럼 보이는 숫자가 있으면 서버가 저장을 거부합니다. 요청자 사번은 본인 확인용으로만 서버에 보관하며 화면·백업에는 내보내지 않습니다.

### 저장 안전장치

- 파일 저장은 임시 파일에 끝까지 쓴 뒤 이름을 바꿔 교체합니다(저장 도중 오류가 나도 기존 데이터 유지). 교체 직전 파일은 `.bak`으로 한 벌 남깁니다.
- 같은 파일에 대한 쓰기는 한 줄로 세워 처리하고, 콘텐츠 수정은 버전이 어긋나면(다른 곳에서 먼저 수정) 덮어쓰지 않고 거부합니다.
- 저장 파일이 깨졌거나 더 새로운 형식이면 **아무것도 쓰거나 초기화하지 않고** 오류를 알립니다(파일은 그대로 보존).
- **서버 프로세스가 1개일 때만 안전합니다.** 파일 잠금은 프로세스 안에서만 작동하므로, 인스턴스가 여러 개이면 서로의 쓰기를 막지 못합니다. 이 앱은 플랫폼의 인스턴스 수를 알 수 없습니다.

### 저장 상태 표시

관리자 화면(콘텐츠 관리)과 각 화면의 경고 배너는 **실제 저장 폴더의 지정 여부와 쓰기 가능 여부**(쓰기 시험)로 판단합니다.

- 폴더가 지정되어 있고 쓸 수 있음 → "저장 폴더 확인됨"(영구 보관·백업 여부는 확인 불가라고 함께 표시)
- `APP_DATA_DIR` 없음 → 시작 스크립트가 임시 폴더(`/tmp/hycg-data`)로 대체하고 `HYCG_DATA_DIR_TEMP=1`을 설정 → "임시 저장(재배포하면 사라짐)"
- 폴더에 쓸 수 없음 → "저장 불가", 저장 요청은 성공한 척하지 않고 오류를 돌려줌

### 관리자 백업·복구 (콘텐츠 관리 화면 맨 위)

배포 환경이 `APP_DATA_DIR`을 자동으로 백업하지 않을 수 있으므로, 관리자가 주기적으로 백업 파일을 내려받아 보관하는 것을 권합니다.

- **내려받기**(관리자만): CMS 콘텐츠 변경분과 개선 요청을 JSON으로 저장합니다. 기본 안내를 수정한 것(`modifiedSeed`)과 관리자가 추가한 것(`added`)을 구분해 담고, 검증 값(checksum)이 들어갑니다. 비밀번호·비밀키·직원 명단·접속 기록·개인 보관함, 요청자 ID, **개선 요청 첨부 파일은 항상 제외**됩니다. 안내문 원본 첨부는 체크했을 때만 포함됩니다.
- **복구**(관리자만): 파일을 고르면 먼저 미리보기만 보여 주고(아무것도 바뀌지 않음), 관리자가 확인(체크)해야 적용됩니다. 기본은 "서버에 없는 것만 추가"이며, 같은 ID로 내용이 다른 기존 콘텐츠는 **관리자가 하나씩 선택한 것만** 덮어씁니다(기존 개선 요청은 덮어쓰지 않음). 미리보기 이후 서버 데이터가 바뀌었거나 파일이 변조되었으면 거부합니다. 적용 직전 데이터는 `cms/backups/`에 자동 복사됩니다.
- **예전 브라우저 데이터 옮기기**: 예전 방식으로 이 PC의 브라우저에 남아 있는 콘텐츠·개선 요청이 있으면 같은 화면에 안내가 나타나며, 미리보기·확인 후 서버로 옮길 수 있습니다. 새로 등록했던 콘텐츠는 안전을 위해 "검토 대기"로 옮겨지고, 기본 안내와 번호가 겹치면 새 번호를 받습니다.

아직 브라우저(localStorage)에만 남는 것은 안내 제공 기록 일부(`hycg.sendlog.v2`, 환자 식별정보 없음), 구성 초안, 인쇄 설정뿐입니다.

## 6. 이미지 빌드와 로컬 시험

이미지 정의(`Dockerfile`) 관련 주의: 외부 이미지를 내려받는 `# syntax` 지시문과 BuildKit 전용 `--chmod`는 쓰지 않습니다(격리망·구형 빌더 대비). `/app`은 root 소유이고 파일만 `COPY --chown=node:node`로 node 소유가 되므로, 시작 스크립트는 `sed -i`(파일 옆에 임시 파일 생성)를 쓰지 않고 `/tmp`의 임시 파일을 거쳐 원래 파일을 덮어씁니다.


```bash
docker build -t hy-care-guide .
```

```bash
docker run --rm -p 8000:8000 -e APP_BASE_PATH=/apps/test -e APP_DATA_DIR=/data -e SESSION_SECRET=<임의 문자열> -v hycg-data:/data hy-care-guide
```

- 이미지는 `RUN chown -R`을 쓰지 않고 `COPY --chown=node:node`를 씁니다.
- `/data`(APP_DATA_DIR) 볼륨이 root 소유라 쓰기 경고가 나오면, 플랫폼 정책에 맞게 폴더 권한을 조정하거나 `Dockerfile`의 `USER node` 줄 처리를 담당자와 상의하세요.
- 접속 예: `http://localhost:8000/apps/test/login`. 앞부분 없이 `http://localhost:8000/login`으로 접속하면 404가 정상입니다.

## 7. 플랫폼 담당자에게 확인할 사항

1. 앱 공개 범위·보안 요건: 직원 이름·사번이 서버 파일에 저장됩니다. 이에 맞는 공개 범위와 보안 요건.
2. 환자 접속 경로: 환자용 링크(`/c/…`)를 사내망 밖의 환자에게 열어 줄 수 있는지(현재 사내망 전용이면 문자·QR 안내는 병원 내부 Wi-Fi에서만 열림).
3. `APP_DATA_DIR`: 영구 보존 여부, 소유권·권한(컨테이너 사용자 `node` 쓰기 가능 여부), 용량, **백업 여부**(없다면 관리자 수동 백업으로 대응), 컨테이너를 재생성·롤백할 때 폴더가 유지되는지.
4. **단일 인스턴스 여부**: 여러 인스턴스로 실행되면 서버 JSON 파일 저장(프로세스 내 직렬화)이 서로 충돌해 데이터가 유실될 수 있습니다. **확인되기 전까지 이 저장 구조의 안전성은 보장되지 않습니다.** 여러 인스턴스라면 공유 저장소나 DB가 필요합니다.
5. 프록시: `X-Forwarded-Proto`, `X-Forwarded-Host` 전달 여부, http/https 구분.
6. 빌드 환경: npm 레지스트리 접근, 기본 이미지(`node:22-bookworm-slim`) 가져오기 가능 여부.
7. SSO 등 사번 전달 방식이 있는지(현재는 앱 자체의 이름+사번 로그인 사용).
8. 배포 권한과 접속 공개 절차.

## 8. 글꼴

Google 글꼴 서버에 접속하지 않습니다. Noto Sans KR(SIL OFL 1.1) 파일이 저장소 `src/app/fonts/`에 들어 있고, 글꼴 파일이 없는 환경에서는 Pretendard·맑은 고딕·Apple SD Gothic Neo 같은 시스템 글꼴로 대체됩니다. 라이선스 전문은 `src/app/fonts/noto-sans-kr/LICENSE.txt`에 있습니다.

## 9. 알려진 제한

- http 주소에서는 브라우저가 Clipboard API를 막습니다. "링크·문구 복사" 버튼은 이 경우 숨은 입력칸을 이용한 대체 방법으로 복사하며, 그것도 막히면 "복사되었습니다"라고 표시하지 않고 직접 복사하도록 안내합니다(링크와 문구는 한 번 눌러 전체 선택할 수 있음).
- 서버 저장소는 단일 인스턴스·파일 시스템 영구 보존이 전제이며, 앱은 이 둘을 확인할 수 없습니다(7항 확인 필요). 자동 백업이 없다면 관리자의 수동 백업이 유일한 복구 수단입니다.
- 개선 요청 첨부 파일은 백업에 포함되지 않습니다(환자 정보가 있을 수 있어). 서버 폴더를 잃으면 첨부는 복구할 수 없습니다.
- 같은 파일에 대한 동시 저장 보호는 서버 프로세스 1개 안에서만 유효합니다.
- 이 문서의 시험(앞부분 포함/없는 실행, 쿠키, 저장)은 Docker 없이 standalone 빌드와 시작 스크립트를 로컬에서 그대로 실행해 확인했습니다. **Docker 이미지 자체의 빌드·실행은 플랫폼 또는 Docker가 있는 PC에서 한 번 더 확인이 필요합니다.**

# PLAN — HY CARE GUIDE Phase 1 빌드 계획

## 이번 사이클 목표

PRD.md에 정의된 Phase 1 범위(EMR-free 환자 안내 콘텐츠 전달 지원 시스템)의 기능
전체를, 의존성이 먼저 해결되는 순서로 빠짐없이 구현한다.

## 성공 기준

- PRD.md 6장의 성공 기준 7개 항목을 모두 충족한다.
- `npm run lint`, `npm run build`가 오류 없이 통과한다.
- 아래 작업 목록 16개 항목이 실제 코드에 전부 반영되어 있다(작업목록 vs 코드 대조 시 누락 0건).

## 작업 목록 (선행 작업 → 후행 작업 순)

1. 콘텐츠·발송 이력 타입 정의 (`GuideContent`, `SendLogEntry`, `DeliveryChannel` 등 스키마 확정)
2. 5개 카테고리 요건(검사15/수술10/입원9/퇴원8/기타8)을 충족하는 콘텐츠 시드 데이터 50건 작성
3. localStorage 읽기·쓰기 유틸 및 SSR-세이프 클라이언트 값 훅 구현
4. 배포 도메인에 종속되지 않는 origin 동적 해석 로직 구현 (클라이언트: `window.location.origin`, 서버: 요청 Host 헤더)
5. SMS/카카오 문구 및 콘텐츠 고정 링크 생성 로직 구현 (실제 발송 API 호출 없이 문구 생성까지만)
6. 4개 메뉴(환자 안내 콘텐츠/콘텐츠 관리/발송 이력/통계) 공통 레이아웃과 반응형 내비게이션 구현
7. 직원 홈: 콘텐츠 검색·카테고리/진료과/여정단계 필터 화면 구현
8. 콘텐츠 미리보기 모달 구현 (단계별 안내, FAQ, 위치/연락처 표시)
9. 발송 어시스턴트 모달 구현 (SMS/QR/카카오 3채널, 실제 클릭 시에만 이력 기록)
10. 환자용 콘텐츠 상세 페이지(`/c/[slug]`) 구현 (게시 상태 검사, `tel:` 링크, OG 메타태그, 16px 이상 본문)
11. 콘텐츠 관리(CMS) 화면 구현 (등록·수정·게시/비게시 전환)
12. 발송 이력 화면 구현 (발송 시각·콘텐츠·채널·완료 여부만 표시)
13. 통계 대시보드 구현 (카테고리별·채널별 집계)
14. PII 제로 셀프 점검 및 수정 (이름/등록번호/전화번호 패턴, 하드코딩 예시 전수 검사)
15. 모바일(360~430px)·태블릿(768px) 반응형 검증 및 레이아웃 수정
16. `npm run lint` / `npm run build` 최종 검증

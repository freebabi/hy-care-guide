# 인쇄·PDF 시험 보고서 (PDF_PRINT_TEST_REPORT)

작성: 2026-11-11 · 대상: `안내자료 구성 → 인쇄용 화면`(`/compose/print`)
**분류 표기**: 🟢 개발 완료 · 🟡 추가 개발 필요 · 🔵 병원 정보팀 확인 필요 · 🔴 병원 보안 승인 필요

## 한눈에 보기 (쉬운 설명)

- 안내자료를 여러 개 묶어 **A4 세로·A4 가로·A3** 로 인쇄하거나 **PDF로 저장**할 때, 글자·이미지가 잘리지 않고 메뉴·버튼이 찍히지 않는지 **실제 PDF를 만들어서** 확인했습니다. 쪽수·용지 크기를 측정하고, 이미지가 있는 쪽은 **눈으로 직접** 봤습니다.
- 확인 중 문제 4개를 찾아 고쳤습니다(아래 3절). 예) 화면 안내용 "눌러서 크게 보기" 배지가 인쇄물에 찍히던 것, 마지막 안내 문장 두 줄이 혼자 한 쪽을 차지하던 것, **저장한 인쇄 설정이 열 때마다 기본값으로 지워지던 버그**.
- **직접 PDF 파일 다운로드 버튼은 만들지 않았습니다.** 브라우저의 인쇄 창에서 "PDF로 저장"을 고르는 방식이며, 화면에서 **"프린터로 인쇄"와 "PDF 파일로 저장"을 따로** 보여주고 각각 안내를 붙였습니다. 직접 다운로드가 꼭 필요한지는 5절에서 검토했습니다(현재는 불필요).
- 한계: 실제 **종이 프린터로는 출력해 보지 못했고**, 시험은 **Chrome**으로만 했습니다(Edge·Firefox는 같은 방식이지만 미확인).

---

## 1. 시험 방법

- 시험용 임시 서버·가짜 직원 계정으로 `인쇄용 화면`을 열고, **설치된 Chrome(헤드리스)** 으로 실제 PDF를 생성했습니다(`@page` 용지 설정을 그대로 따르는 모드, 배경색 포함).
- 안내자료 **11건**(CT·MRI·X-ray + 신규 반영 8건, 이미지 10장 포함)을 한 묶음으로 인쇄했습니다.
- 생성된 PDF에서 **쪽수·용지 크기·이미지 수**를 읽고, 쪽마다 글자 수를 세어 "거의 빈 쪽"을 찾고, 대표 쪽은 **이미지로 변환해 눈으로 확인**했습니다.
- 인쇄 모드에서 화면 요소(상단 메뉴·하단 푸터·인쇄 설정·"눌러서 크게 보기" 배지)가 숨겨지는지 계산된 스타일로 확인했습니다.

## 3. 항목별 확인 (요청하신 12개 항목)

| 항목 | 결과 |
|---|---|
| **A4 세로** | 🟢 용지 210×297mm 정확히 적용 |
| **A4 가로** | 🟢 297×210mm 적용. 글줄이 너무 길지 않게 본문 폭 제한 |
| **A3 인쇄** | 🟢 A3 세로·가로 모두 적용. 처음에는 A4와 같은 글자 크기라 A3 종이에서 너무 작아 보여, **A3일 때 내용을 약 1.41배(용지 비율)로 확대**하도록 개선 후 눈으로 확인 |
| **이미지 해상도** | 🟢/🔵 아래 표. A4에서 238~382dpi로 선명. A3는 내용을 확대해 인쇄하므로 가로 그림이 **A3 세로 162~261dpi, A3 가로 116~186dpi**로 낮아짐(가장 낮은 것은 A3 가로의 낙상 호출벨·병동 입구·응급 수술 보호자 약 116~120dpi) → A3로 크게 출력할 자료는 **원본 고해상도 파일**로 교체 권장 🔵 |
| **페이지 넘김** | 🟢 자료마다 새 쪽에서 시작(끌 수 있음). 표지(제목·목차·승인 전 자료 경고) 한 쪽 + 자료별 쪽 |
| **제목과 본문 분리** | 🟢 소제목은 다음 내용과 붙어 다님(쪽 맨 아래에 제목만 남지 않도록 규칙 적용). 눈으로 확인한 쪽에서 문제 없음 |
| **이미지 잘림** | 🟢 이미지·박스·번호 단계 항목은 쪽 경계에서 **쪼개지지 않고 통째로 다음 쪽으로 이동**. A4 세로 6쪽, A4 가로 4쪽, A3 세로·가로 샘플 쪽을 눈으로 확인 — 잘린 이미지 없음 |
| **다중 안내자료 결합** | 🟢 11건 → 한 파일(31쪽). 각 자료 앞에 `n / 11` 표시. 공식 승인 전 자료가 있으면 **표지에 경고**, 각 자료에도 기존의 "승인 전" 안내 문구 유지. 내용은 환자용 상세 화면과 같은 컴포넌트를 써서 **원본 내용을 바꾸지 않음** |
| **메뉴·버튼 숨김** | 🟢 상단 메뉴·하단 푸터·인쇄 설정 패널·"눌러서 크게 보기" 배지가 인쇄에서 숨겨짐(5개 조건 모두 확인) |
| **배경·색상 출력** | 🟢 경고·안내 박스의 색이 유지되도록 설정(기본 켜짐). 끄면 브라우저 인쇄 창의 "배경 그래픽" 설정을 따름 |
| **여백** | 🟢 보통(위아래 14mm·좌우 12mm) / 좁게(8mm) 선택, 직접 용지 여백이 인쇄 창과 일치하도록 `@page`로 지정 |
| **PDF 저장 vs 일반 인쇄 구분** | 🟢 "프린터로 인쇄"(종이)와 "PDF 파일로 저장"(파일) 버튼·설명 분리. PDF 버튼은 "인쇄 창에서 **PDF로 저장** 선택" 3단계 안내 창을 먼저 보여줌 |

### 이미지 해상도 (15장, 본문 폭 기준 실효 dpi)
| 구분 | A4 세로 | A4 가로 | A3 세로(1.41배 확대) | A3 가로(1.41배 확대) |
|---|---|---|---|---|
| 세로 포스터형 7장(1400×~1980px) | **307dpi** | 307dpi | 약 216dpi | 약 216dpi |
| 가로형 8장(1742~2800px) | **238~382dpi** | 약 188~303dpi | **162~261dpi** | **116~186dpi** (가장 낮음) |

※ 인쇄된 이미지의 실제 가로 길이(A3 가로는 약 380mm)로 계산한 값입니다. A4 가로는 본문 폭 제한(235mm)으로 계산했습니다.

일반적으로 인쇄는 150dpi 이상이면 읽을 수 있고 300dpi가 선명합니다. A3 가로에서 가장 낮은 약 116dpi(1742px 그림)는 **작은 글씨가 흐릿할 수 있어** 해당 자료를 A3 가로로 크게 출력할 계획이면 원본 고해상도 파일이 필요합니다. (이 수치는 계산값이며, A3 실제 출력물의 선명도는 확인하지 못했습니다.)

## 4. 시험 중 발견해서 고친 문제

| 문제 | 영향 | 조치 |
|---|---|---|
| 이미지 위의 "눌러서 크게 보기" 배지가 인쇄물에 찍힘 | 인쇄물이 지저분함 | 인쇄에서 숨김 |
| 자료 끝 안내 문장 두 줄이 **혼자 한 쪽**을 차지 | 종이 낭비·어색함 | 마지막 문장이 앞 내용과 붙어 다니도록 규칙 추가(재시험 결과 A4 세로 거의 빈 쪽 0) |
| 저장한 **인쇄 설정이 열 때마다 기본값으로 덮어써짐**(설정 읽기 전에 저장 코드가 먼저 실행) | 선택한 용지(A3 등)가 PDF에 반영되지 않음(시험에서 4개 설정이 똑같은 PDF로 나와 발견) | 읽기가 끝난 뒤에만 저장하도록 수정, 재시험에서 용지·여백·새 쪽 설정이 모두 PDF에 반영됨 |
| A3에서 글자가 종이에 비해 너무 작음 | 읽기 불편 | A3는 내용 1.41배 확대 |
| 화면 아래쪽의 지연 로딩 이미지가 인쇄에서 비어 나올 수 있음(브라우저 특성) | 이미지 누락 위험 | 인쇄 전에 이미지를 **모두 불러오고 기다린 뒤** 인쇄 창을 엶(이 수정 없이 비교 실험은 하지 않았음. 시험 PDF에서는 이미지 10/10 포함) |
| 직원 화면의 본문 여백·배경이 용지 여백에 더해짐 | 여백 과다 | 인쇄 때 레이아웃 여백 제거 |

## 5. 자동 PDF 다운로드가 필요한가? (검토)

| 방법 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **현재 방식: 브라우저 인쇄 → PDF로 저장** | 추가 라이브러리·서버 부담 0, 글자 선명·검색 가능, 이번에 품질 검증 완료 | 사용자가 인쇄 창에서 한 번 더 선택해야 함 | **유지(권장)** |
| 브라우저에서 PDF 생성 라이브러리(jsPDF·html2canvas 등) | 버튼 한 번에 다운로드 | 한글 글꼴 파일(수 MB) 포함 필요, 글자가 그림이 되기 쉬워 흐리고 검색 불가, 페이지 나눔 직접 구현 → **복잡하고 품질 불안** | 비권장 |
| 서버에서 Chrome으로 PDF 생성 | 품질 최고(이번 시험과 같은 방식) | 서버에 Chrome 설치(컨테이너 커짐), 보안·운영 부담, 외부 통신이 제한된 환경의 정책 확인 필요 | 요구가 확실해지면 검토 🔵 |

**결론**: 지금은 **불필요**합니다. "PDF 파일로 저장" 버튼이 파일을 직접 만든다고 오해하지 않도록 화면에 안내 창을 붙였고, 동작하지 않는 다운로드 버튼은 없습니다. 이력에는 "인쇄 준비"로만 기록되며 PDF 저장 여부는 브라우저가 알려주지 않아 기록하지 않습니다.

## 6. 한계 (솔직한 정리)

- **실제 종이 프린터 출력은 확인하지 못했습니다.** 프린터별 인쇄 가능 영역·드라이버 차이는 현장 시험이 필요합니다 🔵.
- 시험은 **Chrome**에서만 했습니다. Edge(같은 엔진)는 같을 가능성이 높지만 Firefox 등은 쪽 나눔이 다를 수 있습니다 🔵.
- 인쇄 창에서 **배율 100%**, **머리글·바닥글 끄기**를 권장합니다(화면에 안내 문구 표시). 이것은 사용자가 인쇄 창에서 직접 설정해야 합니다.
- 자료 끝에 내용이 적은 꼬리 쪽이 가끔 생길 수 있습니다(A4 가로·A3 가로 각 1쪽).
- 같은 11건이라도 자료 내용이 바뀌면 쪽수는 달라집니다.
- 이미지 원본 해상도 한계(위 표)는 코드로 개선할 수 없고 원본 파일 교체가 필요합니다.

# 운영 준비 현황 요약 (PRODUCTION_READINESS_REPORT)

HY CARE GUIDE의 운영 준비 상태를 한눈에 정리한 공개용 요약입니다. 특정 배포 환경의 내부 운영 절차나 접속 정보는 담지 않았습니다.
**분류 표기**: 🟢 개발 완료 · 🟡 추가 개발 필요 · 🔵 운영 환경·병원 담당 부서 확인 필요 · 🔴 병원 보안 승인 필요

> 세부 내용: `DATABASE_ARCHITECTURE_REVIEW.md` · `AUTHENTICATION_REVIEW.md` · `USER_DATA_SECURITY_REVIEW.md` · `FILE_STORAGE_REVIEW.md` · `PDF_PRINT_TEST_REPORT.md` · `docs/deployment/HY_AGENT_PLACE_DEPLOYMENT.md`

---

## 1. 결론

**소수 직원 대상 시범 운영은 가능하지만, 정식 운영 전에 확인할 것이 남아 있습니다.**

1. **데이터 저장**: 관리자가 수정·등록한 안내 콘텐츠와 직원의 개선 요청이 서버에 저장되어 모든 화면이 같은 내용을 봅니다. 저장은 서버 폴더의 JSON 파일 방식이라 **서버 프로세스 1개와 폴더 영구 보존이 전제**이며, 앱은 이를 확인할 수 없습니다(🔵).
2. **로그인**: 이름 + 사번 로그인이며, 관리자는 이름·사번·비밀번호가 모두 맞아야 합니다. 사번과 이름은 비밀이 아니므로 **구별 장치이지 본인 확인은 아닙니다**(🟡🔵🔴 본인 확인 수단 결정 필요).
3. **의료진 검토**: 신규 등록 콘텐츠는 항상 검토 대기로 시작하고, 검토 대기 콘텐츠는 환자 화면과 인쇄·다운로드·환자 안내 기능에서 서버가 차단합니다.
4. **백업·복구**: 관리자 화면에서 백업 파일 내려받기와 미리보기·확인 후 복구를 할 수 있습니다. 개선 요청 첨부는 백업에서 제외됩니다.
5. **배포**: Docker 배포 설정(8000 포트, `APP_BASE_PATH` 처리, HTTP/HTTPS 로그인 쿠키, 로컬 글꼴)을 갖췄습니다. **실제 Docker 이미지 빌드와 컨테이너 실행은 아직 확인하지 못했습니다.**

## 3. 분류별 할 일

### 🟢 개발 완료
- 이름+사번 로그인, 사번 기반 사용자 고유 ID, 관리자 1명 고정(서버 설정), 서버 측 관리자·직원 권한 검증, 쿠키 위조 방어
- 직원별 개인 데이터 분리, 동명이인 분리, 환자 정보 숫자 패턴 거부, 관리자 활동 기록
- CMS 콘텐츠·개선 요청 서버 공유 저장, 신규 콘텐츠 의료 검토, 관리자 백업·복구, 저장 상태 표시
- 한글 안내 주소(slug) 처리, 인쇄·PDF 설정
- Docker 배포 설정(`Dockerfile`, 시작 스크립트, `APP_BASE_PATH`, 쿠키, 로컬 글꼴)

### 🟡 추가 개발 필요
1. 본인 확인 수단(인사 명부 대조 / 개인 비밀번호 / 이메일 인증 중 병원이 정한 것)
2. 여러 서버로 운영해야 할 경우 저장소를 DB로 전환(저장 함수 교체)
3. 로그인 실패 제한을 여러 서버가 공유(DB), 보존 기간 자동 정리
4. 안내 이미지를 재배포 없이 교체하는 기능, 업로드 파일 바이러스 검사 연동

### 🔵 확인 필요
- 운영 환경: **서버 프로세스 수**, 데이터 폴더의 **영구 보존·권한·용량·백업**, 컨테이너 사용자의 쓰기 권한, 프록시의 `X-Forwarded-Proto` 전달
- **실제 Docker 이미지 빌드·실행**
- 사번 전달(SSO) 방식, 사번 자릿수 규칙, 인사 명부 제공 가능 여부
- 환자용 링크의 외부(원내 밖) 접속 가능 여부
- 실제 프린터와 여러 브라우저의 인쇄 시험, 개인정보 보존 기간

### 🔴 병원 보안 승인 필요
- 직원 사번·이름·활용 이력 저장·처리의 개인정보 승인, 본인 확인 방식 최종 승인
- 외부 클라우드 DB·스토리지 사용
- 실제 SSO 연동, 운영 배포

## 4. 운영 전 체크리스트 (순서)

1. 병원 담당 부서 확인: 서버 수, 데이터 폴더 영구 보존·백업, 직원 정보 저장의 보안 요건·승인, 사번 전달 여부 (🔵🔴)
2. 배포 환경 변수 설정: `SESSION_SECRET`, `ADMIN_PASSWORD`, `ADMIN_EMPLOYEE_ID`, `ADMIN_NAME` (값은 대화·저장소·문서에 적지 않기)
3. Docker 이미지 빌드·실행 확인, 로그의 `APP_BASE_PATH` 적용·`APP_DATA_DIR` 쓰기 확인
4. 관리자 로그인 후 콘텐츠 하나 저장 → **재배포 후 남는지** 확인 → 백업 내려받기 확인
5. 본인 확인 방식 결정 후 로그인 보강
6. 실제 프린터·여러 브라우저 인쇄 시험, 소수 직원 파일럿, 피드백 반영

**임시 시범 운영(최소 구성)**: 서버 1개 고정, 영구 저장 폴더 사용, 관리자의 정기 백업, 승인된 직원만 접속, 소수 직원으로 시작.

## 5. 주의

- `.env.local`과 `.env`에는 관리자 값 등 비밀이 들어갈 수 있으며 `.gitignore`와 `.dockerignore`로 제외됩니다. 소스·문서에는 관리자 실명·사번·비밀번호를 적지 않습니다.
- 병원 원본 자료 폴더(`reference-materials/`)는 개발자 PC에만 두며 Git에서 제외됩니다.
- 사번 없이 쌓였던 예전 직원 데이터 파일은 자동 이전되지 않고 보존만 합니다.
- 브라우저(localStorage)에 남아 있던 예전 CMS 콘텐츠·개선 요청은 관리자 화면의 이전 기능으로 서버에 옮길 수 있습니다(미리보기·확인 후, 신규 콘텐츠는 의료 검토 대기로 저장).

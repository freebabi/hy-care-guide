# 파일 저장소 검토 (FILE_STORAGE_REVIEW)

이 문서는 공개용으로 정리한 일반 기술 문서입니다. 특정 배포 환경의 내부 운영 절차나 접속 정보는 담지 않았습니다.

**분류 표기**: 🟢 개발 완료 · 🟡 추가 개발 필요 · 🔵 운영 환경 확인 필요 · 🔴 병원 보안 승인 필요

---

## 한눈에 보기

- 이 앱의 "파일"은 **세 곳**에 있습니다. ① 소스와 함께 배포하는 **승인된 안내 이미지**, ② 서버 데이터 폴더에 저장되는 **첨부 파일**(안내문 원본·개선 요청 첨부), ③ 개발자 PC에만 두는 **병원 원본 자료**(저장소에 올리지 않음).
- 첨부 파일은 이전에는 각자의 브라우저 안에 저장되어 다른 직원이 볼 수 없었지만, 이제 **서버에 파일로 저장**되어 권한이 있는 사람만 열 수 있습니다.
- 서버 폴더에 저장하는 방식은 **서버 1개 고정**과 **폴더 영구 보존**이 전제이며, 앱은 이 둘을 확인할 수 없습니다(🔵).

---

## 1. 현재 파일이 저장되는 곳

| 구분 | 위치 | 비고 |
|---|---|---|
| 승인된 안내 이미지 43장 | `public/assets/guides/` (소스와 함께 배포) | 읽기 전용 공개 이미지. 이미지를 바꾸려면 **재배포**가 필요 🟡 |
| 안내문 원본 첨부(관리자) | 데이터 폴더 `cms/files/` | 직원만 열람, 게시되지 않은 콘텐츠의 원본은 관리자만 열람 🟢 |
| 개선 요청 첨부 | 데이터 폴더 `cms/files/` | 요청자 본인과 관리자만 열람 🟢 |
| 병원 원본 안내자료 | 개발자 PC의 `reference-materials/` | `.gitignore`로 Git에서 제외, 서버에 올라가지 않음(웹 반영본만 별도로 가공해 사용) 🟢 |

## 2. 현재 첨부 파일 규칙 🟢

- 허용 형식: **PNG·JPG·PDF**, 파일당 **1MB 이하**. PPT는 지원하지 않습니다.
- 확장자와 이름이 아니라 **파일 내용의 시그니처**(PNG·JPEG·PDF 머리 부분)로 형식을 확인하고, 서버가 정한 무작위 이름으로 저장합니다(사용자가 정한 이름은 저장 경로에 쓰지 않음).
- 내려줄 때 `X-Content-Type-Options: nosniff`와 `Content-Security-Policy: default-src 'none'; sandbox`를 붙이고, 이미지가 아니면 내려받기로만 제공합니다.
- 개선 요청은 한 직원이 **시간당 20건**까지, 환자 개인정보로 보이는 숫자 패턴이 있으면 저장을 거부합니다.
- 관리자 백업에는 안내문 원본만 선택 시 포함되고, **개선 요청 첨부는 항상 제외**됩니다(환자 정보가 있을 수 있어서). 서버 폴더를 잃으면 요청 첨부는 복구할 수 없습니다.

## 3. 저장소 후보 비교 (규모가 커지거나 여러 서버가 필요할 때)

| 항목 | 병원 내부 파일 서버(NAS·공유 폴더) | 외부 클라우드 스토리지 | S3 호환 스토리지(내부 설치 시) | 현재 방식(서버 데이터 폴더) |
|---|---|---|---|---|
| 위치 | 병원 안 | 병원 밖 | 병원 안 또는 밖 | 병원 안, 앱 전용 폴더 |
| 보안·승인 | 🔵 내부 정책 | 🔴 직원·업무 자료가 외부로 나가므로 보안 승인 필수 | 내부 설치면 🔵, 외부면 🔴 | 배포 환경 정책 안에서 사용 |
| 앱 연결 난이도 | 중간(마운트·계정·네트워크). 외부 통신이 제한된 환경에서는 직접 연결이 안 될 수 있음 🔵 | 낮음(SDK) | 중간(서명 URL) | 가장 낮음 |
| 백업·복구 | 병원 백업 정책 🔵 | 자동(요금제별) | 설정에 따름 | 환경에 따라 다름 🔵, 관리자 수동 백업 필요 |
| 접근 통제 | 폴더 권한 | 정책·서명 URL | 버킷 정책·서명 URL | 앱이 직접 통제 |

**권고(병원 내부 우선)**
1. **시범 운영**: 현재 방식(서버 데이터 폴더) + 관리자 정기 백업.
2. **정식 운영**: 병원이 승인한 내부 파일 서버 또는 내부 S3 호환 스토리지로 이전.
3. 외부 클라우드 스토리지는 🔴 보안 승인 전에는 사용하지 않습니다.

## 4. 저장소 전환 시 설계 원칙 🟡

- **파일 내용은 파일 저장소에, DB에는 파일 정보와 경로만** 저장합니다(바이너리 열을 두지 않음).
- 파일을 공개 주소로 열어두지 않고, 앱이 권한을 확인한 뒤 서버가 중계하거나 짧게 유효한 서명 주소로 내려줍니다.
- 승인 전 자료는 공식 자료처럼 표시하지 않는 현재 원칙을 유지합니다(환자 화면에는 승인된 이미지만).
- 업로드·삭제를 관리자 활동 기록에 남기고, 필요하면 바이러스 검사 도구를 연결합니다 🔵.
